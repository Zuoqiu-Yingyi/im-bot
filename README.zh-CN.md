# 思源 IM 机器人

一款把 QQ 机器人、微信 ClawBot、Telegram 机器人与飞书机器人接入[思源笔记](https://github.com/siyuan-note/siyuan)的插件：把 QQ 群里的消息、发给微信 ClawBot 的消息、Telegram 私聊、群组与频道的消息以及飞书单聊与群聊的消息记录到思源的收集箱文档中，并提供查询 OpenID 与会话 ID 的指令、向已知的群与用户发送消息的页签与 QQ 机器人接口调试工具。

插件的主要功能运行在思源内核中，思源运行时即可工作，不需要打开思源的界面。需要思源 3.7.3 或更高版本。

## 快速开始

1. 在 [QQ 开放平台](https://q.qq.com/)创建机器人，在机器人的开发设置中获取 AppID 与 AppSecret，并在「事件订阅与回调地址」中选择 WebSocket 方式。
2. 把机器人添加到要记录的 QQ 群，由群主为机器人打开「获取群内全部消息」。
3. 在本插件的设置中填写 `QQ 机器人 > 机器人 > AppID` 与 `QQ 机器人 > 机器人 > AppSecret`，再打开 `QQ 机器人 > 机器人 > 上线`（默认关闭）。
4. 群主在群里 @ 机器人发送 `/openid`，机器人会回复该群的 group_openid。
5. 在 `QQ 机器人 > 收集箱 > 绑定群聊` 中点击「添加绑定」，填写 group_openid 与用来收集消息的文档的 ID，再打开该绑定的「启用」（新建的绑定默认不启用）。

之后该群的消息都会记录到这篇文档下按日期组织的子文档中。

接入微信 ClawBot：

1. 在 `微信机器人 > 机器人 > 微信账号` 中点击「扫码登录」，用手机微信扫描二维码，并在手机上确认。
2. 在 `微信机器人 > 收集箱 > 收集箱文档 ID` 中填写用来收集消息的文档的 ID，再打开 `微信机器人 > 机器人 > 上线`（默认关闭）。

之后在微信中发给这个 ClawBot 的消息都会记录到这篇文档下按日期组织的子文档中。

接入 Telegram 机器人：

1. 在 Telegram 中向 [@BotFather](https://t.me/BotFather) 发送 `/newbot` 创建机器人，获取它的 Token。要记录群组中的全部消息，先向 @BotFather 发送 `/setprivacy` 关闭该机器人的隐私模式，再把机器人添加到群组（已在群组中的机器人要移出后重新添加才生效），或者把机器人设为群组管理员；要记录频道的消息，把机器人添加为频道管理员。
2. 在 `Telegram 机器人 > 机器人 > Token` 中填写 Token，再打开 `Telegram 机器人 > 机器人 > 上线`（默认关闭）。
3. 私聊中向机器人发送 `/chatid`；群组中由群主或管理员发送 `/chatid@机器人用户名`；频道中发布 `/chatid`（机器人的回复会出现在频道中，查到后可以删除）。机器人会回复该会话的 ID。
4. 在 `Telegram 机器人 > 收集箱 > 绑定会话` 中点击「添加绑定」，填写会话 ID 与用来收集消息的文档的 ID，再打开该绑定的「启用」（新建的绑定默认不启用）。

之后该会话的消息都会记录到这篇文档下按日期组织的子文档中。

接入飞书机器人：

1. 在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用，在「应用能力 > 添加应用能力」中添加「机器人」，并在「基础信息 > 凭证与基础信息」中获取 App ID 与 App Secret。
2. 在「开发配置 > 权限管理」中开通以下应用身份权限：`im:message`（获取与发送单聊、群组消息）、`im:message.p2p_msg:readonly`（读取用户发给机器人的单聊消息）、`im:message.group_at_msg:readonly`（接收群聊中 @ 机器人消息事件）与 `im:chat:readonly`（获取群组信息）。要记录群里的全部消息，还要开通敏感权限 `im:message.group_msg`（获取群组中所有消息）。
3. 在「应用发布 > 版本管理与发布」中创建版本并发布，可用范围要包含使用机器人的成员。机器人能力与权限在发布后才生效，可能需要企业管理员审核；插件要先获取机器人的信息才能连接飞书，所以要先发布一次。
4. 在本插件的设置中填写 `飞书机器人 > 机器人 > App ID` 与 `飞书机器人 > 机器人 > App Secret`，再打开 `飞书机器人 > 机器人 > 上线`（默认关闭），等待 `飞书机器人 > 机器人 > 连接状态` 显示「已连接」。
5. 在「开发配置 > 事件与回调 > 事件配置」中把订阅方式设为「使用长连接接收事件」并保存（飞书要求保存时已有长连接在线，所以要先完成上一步），再添加事件「接收消息」（`im.message.receive_v1`）。
6. 再次创建版本并发布，让「接收消息」事件生效。
7. 单聊中向机器人发送 `/chatid`；群聊中先把机器人添加到群里，再由群主或群管理员 @ 机器人发送 `/chatid`。机器人会回复该会话的 ID。
8. 在 `飞书机器人 > 收集箱 > 绑定会话` 中点击「添加绑定」，填写会话 ID 与用来收集消息的文档的 ID，再打开该绑定的「启用」（新建的绑定默认不启用）。

之后该会话的消息都会记录到这篇文档下按日期组织的子文档中。

## 常见问题

- 收集箱里没有新消息？

  - 检查 `QQ 机器人 > 机器人 > 上线` 是否开启。该开关默认关闭，关闭时机器人不连接 QQ。
  - 群主需要为机器人打开「获取群内全部消息」。否则机器人只能收到 @ 它的消息，而这些消息都视为指令，不会写入收集箱。
  - 检查绑定是否开启了「启用」，group_openid 与文档 ID 是否正确，`QQ 机器人 > 机器人 > 订阅事件` 中是否开启了「群聊与单聊」。
  - 开启了 `QQ 机器人 > 机器人 > 只在此设备上运行` 时，只有指定的设备会写入收集箱。
- 机器人没有连接或没有响应？

  - 在 `QQ 机器人 > 机器人 > 连接状态` 中查看本设备的连接状态，连接断开或停止时会显示原因。显示「已下线」时打开 `QQ 机器人 > 机器人 > 上线`。
  - 查看工作空间内核日志 `temp/siyuan.log` 中含有 `[plugin:im-bot]` 的记录。
  - AppID 或 AppSecret 错误，或者订阅了没有权限的事件类别时，插件会停止重连，`连接状态` 中会显示原因；修改设置（如 AppID、AppSecret 或订阅事件）或者重新启用插件后才会再次连接。
  - 如果在 QQ 开放平台为机器人设置了 IP 白名单，需要把运行思源的设备的公网 IP 加入白名单。
- 开启了「回复块链接」，但没有收到回复？

  - 被动回复只能在收到消息后 5 分钟内发送，每条消息最多回复 5 次。
  - QQ 要求机器人消息中的链接域名先在开放平台报备（消息 URL 白名单，域名需要 ICP 备案），`siyuan://` 链接可能因此被拒绝（错误码 40054010）。插件还没有在真实的 QQ 群中验证过这一点，失败的原因可以在内核日志中查看。
- 多台设备都安装了本插件？

  - 插件的设置会随数据同步。没有指定运行设备时，每台设备都会各自连接机器人并写入收集箱，可能产生重复的消息或同步冲突。建议在一台常开的设备上开启 `QQ 机器人 > 机器人 > 只在此设备上运行`。
- AppSecret 安全吗？

  - AppSecret 以明文保存在工作空间的 `data/storage/petal/im-bot/config.json` 中，会随数据同步。能调用本工作空间内核接口的程序（包括其他插件）都能读取这个文件。
  - 插件提供的内核接口（RPC 方法 `call-qq-api` 以机器人的身份调用 QQ 机器人接口，`get-users` 返回已知的群与单聊用户），上述程序也都可以使用它们；它们不会返回 AppSecret 与接口调用凭证。
- 微信消息没有写入收集箱？

  - 在 `微信机器人 > 机器人 > 微信账号` 中查看状态：显示「已下线」时打开 `微信机器人 > 机器人 > 上线`；登录失效时需要重新扫码登录；只有扫码登录的设备会接收消息。
  - 检查 `微信机器人 > 收集箱 > 收集箱文档 ID` 是否正确，`写入收集箱` 是否开启。
  - 查看内核日志中含有 `[plugin:im-bot] [weixin]` 的记录。
- 微信 ClawBot 有哪些限制？

  - 只能与扫码登录的微信用户一对一私聊，不能加入群聊，其他人也不能添加它。
  - 图片、语音、文件与视频是加密保存在微信 CDN 上的，只有思源内核提供 `siyuan.crypto`（并支持 AES-ECB）时才能解密并保存到工作空间，否则只记录为占位文本（语音附上微信的语音转文字）。
  - 语音保存为微信的 SILK 格式，思源无法直接播放，消息中保留语音转文字。超过 100 MB 的媒体不会下载。
  - 「回复块链接」是收到消息后立即发送的回复。微信没有公开回复的条数与时效限制，社区观测到每条消息之后最多回复约 10 条。回复返回成功却没有消息 ID 时，消息可能没有送达，内核日志中会有警告。主动推送更不可靠，所以插件不向微信发送上线与下线通知。
  - 本插件通过与微信官方 OpenClaw 插件相同的接口（iLink Bot API）接入，微信没有公开说明其他客户端能否使用这一接口。
- 微信的登录信息安全吗？

  - 登录凭证（bot_token）以明文保存在工作空间的 `data/storage/petal/im-bot/weixin/<机器人 ID>/auth.json` 中，会随数据同步。能调用本工作空间内核接口的程序（包括其他插件）都能读取这个文件。
  - 插件提供的微信相关内核接口不会返回 bot_token。登录二维码在本地生成；扫码的人就是能与机器人对话的人，不要把二维码发给别人。
- Telegram 消息没有写入收集箱？

  - 在 `Telegram 机器人 > 机器人 > 连接状态` 中查看本设备的状态，停止接收时会显示原因。显示「已下线」时打开 `Telegram 机器人 > 机器人 > 上线`。
  - 群组中：机器人默认开启隐私模式，只能收到发给它的指令、回复它的消息等少数消息。要记录全部消息，需要向 @BotFather 发送 `/setprivacy` 关闭隐私模式，然后把机器人移出群组再重新添加（Telegram 要求重新添加后才生效）；或者把机器人设为群组管理员。
  - 频道中：机器人需要是频道的成员（通常需要设为管理员）才能收到频道消息。
  - 普通群组升级为超级群组后，会话 ID 会改变（变为以 `-100` 开头的新 ID），内核日志中会有警告，需要用新的会话 ID 更新绑定。
  - 检查绑定是否开启了「启用」，会话 ID 与文档 ID 是否正确。开启了 `只在此设备上运行` 时，只有指定的设备会写入收集箱。
  - 查看内核日志中含有 `[plugin:im-bot] [telegram]` 的记录。
- Telegram 的连接状态显示「已停止接收」？

  - Token 错误、Token 格式不正确或 Bot API 地址错误时，插件停止接收。修改设置（如 Token、Bot API 地址）或者重新启用插件后才会再次连接。
  - 机器人设置了 Webhook 时，Telegram 不允许用本插件的方式（getUpdates）接收消息。请先删除 Webhook，例如在浏览器中打开 `https://api.telegram.org/bot<Token>/deleteWebhook`。
  - 同一个机器人同一时间只能被一个程序接收消息：另一台设备上的思源或其他机器人程序也在接收时，后开始接收的一方会让先前的一方收到冲突错误（错误码 409），本插件收到该错误后停止接收。有多台设备时请开启 `只在此设备上运行`，并停止其他使用该 Token 的程序。
- Telegram 的 Token 安全吗？

  - Token 以明文保存在工作空间的 `data/storage/petal/im-bot/config.json` 中，会随数据同步。能调用本工作空间内核接口的程序（包括其他插件）都能读取这个文件。拿到 Token 的人可以完全控制这个机器人，泄露后请向 @BotFather 发送 `/revoke` 更换 Token。
  - 插件写入日志与返回给设置面板的错误信息中，Token 的密钥部分会替换为 `***`。
  - 每个请求都会把 Token 发送到 `Bot API 地址`，只填写你信任的服务器。
- 飞书消息没有写入收集箱？

  - 在 `飞书机器人 > 机器人 > 连接状态` 中查看本设备的状态，连接断开或停止时会显示原因。显示「已下线」时打开 `飞书机器人 > 机器人 > 上线`。
  - 已连接却收不到消息时，检查开发者后台：订阅方式是否为「使用长连接接收事件」，是否添加了「接收消息」事件并开通了对应的权限，修改后是否已经发布版本。权限与事件都要发布后才生效，需要审核的权限在审核通过后才生效。
  - 群聊中：机器人要在群里。只开通了 `im:message.group_at_msg:readonly` 时，只能收到 @ 机器人的消息；要记录全部消息，需要开通 `im:message.group_msg`。
  - 检查绑定是否开启了「启用」，会话 ID 与文档 ID 是否正确。开启了 `只在此设备上运行` 时，只有指定的设备会写入收集箱。
  - 飞书把每个事件只推送给应用的其中一个长连接。另一台设备上的思源或其他程序也用这个应用连接飞书时，消息会随机分散到各个程序。有多台设备时请开启 `只在此设备上运行`，并停止其他使用该应用接收事件的程序。
  - 查看内核日志中含有 `[plugin:im-bot] [feishu]` 的记录。
- 飞书的连接状态一直显示「连接已断开」？

  - 原因中提到获取机器人信息（`bot/v3/info` 或 `bot info`）时：插件连接前要先获取机器人的名称与 open_id，需要应用已经添加机器人能力并发布了版本，见「快速开始」。
- 飞书的连接状态显示「已停止连接」？

  - App ID 或 App Secret 错误，或者开放平台地址无效时，插件停止连接。修改设置（如 App ID、App Secret 或开放平台地址）或者重新启用插件后才会再次连接。
  - 在开发者后台重置 App Secret 后，飞书会断开已有的长连接，插件随后停止连接，需要填写新的 App Secret。
- 飞书的 App Secret 安全吗？

  - App Secret 以明文保存在工作空间的 `data/storage/petal/im-bot/config.json` 中，会随数据同步。能调用本工作空间内核接口的程序（包括其他插件）都能读取这个文件。拿到 App Secret 的人可以以这个应用的身份调用开放平台接口、接收它的事件，泄露后请在开发者后台的「凭证与基础信息」中重置。
  - App Secret 与接口调用凭证（tenant_access_token）只发送到 `开放平台地址`。插件不会把它们写入日志，连接状态与其中的错误信息里也不会出现它们。
- 引用消息中块引用的锚文本变了？

  - 收集箱中引用消息与回复消息的块引用使用动态锚文本：被引用的消息改变后（例如在思源中编辑了它），思源按它的第一个块重新生成锚文本。被引用的消息本身也是引用消息时，它的第一个块是它自己的引述块，锚文本会变成它所引用的内容。需要固定锚文本时，可以在块引用的右键菜单中把它改为静态锚文本。

## 介绍

### 功能介绍

- 连接 QQ 机器人

  - 打开 `QQ 机器人 > 机器人 > 上线` 后，插件在思源内核中通过 WebSocket 连接 QQ 机器人，断线后自动重连，重连间隔从 1 秒逐步增加到 60 秒。关闭该开关后断开连接，下线期间的事件不会记录，再次上线后也不会补收。
  - 本设备的连接状态显示在 `QQ 机器人 > 机器人 > 连接状态` 中。
  - 收到的事件都会记录到内核日志中，开启 `QQ 机器人 > 机器人 > 事件日志` 时还会保存为文件。
- 已知的群与单聊用户

  - QQ 没有列出机器人所在的群与单聊用户的接口，插件根据收到的事件把它们记录在工作空间的 `data/storage/petal/im-bot/qq/<AppID>/chats.json` 中（会随数据同步），可以从中查找 group_openid 与 user_openid。这些事件属于 `QQ 机器人 > 机器人 > 订阅事件` 中的「群聊与单聊」。
  - 只有在事件中出现过的群与用户才会被记录：插件开始运行之前机器人就在的群，要等该群有了新消息才会出现。
  - 每个机器人（AppID）一个文件（OpenID 只对同一个机器人有效），其中 `groups` 以 group_openid 为键记录群，`users` 以 user_openid 为键记录单聊用户。时间取自事件，都是 UTC 时间。
  - 群的记录

    - `status`：`added` 表示机器人在群中，`removed` 表示机器人已被移出群
    - `name`：群名称。QQ 的事件中没有群名称，取自最近一次成功的查询群信息（`GET /v2/groups/{group_openid}/info`，如「发送消息」页签中的「查询群信息」），该接口仅对白名单机器人开放
    - `firstSeen`：记录到的最早一个事件的时间
    - `added`、`removed`：最近一次机器人被添加到群、被移出群的时间，以及操作人的 member_openid
    - `proactive`：最近一次群管理员开启或关闭机器人主动消息的结果 `allowed`、时间与操作人
    - `lastMessage`：最近一条群消息的时间
    - `owner`：最近一条由群主发送的消息中，群主的 member_openid 与昵称
  - 单聊用户的记录

    - `status`：`added` 表示用户已添加机器人，`removed` 表示用户已删除机器人
    - `firstSeen`：记录到的最早一个事件的时间
    - `unionOpenid`：用户的 union_openid
    - `added`、`removed`：最近一次用户添加、删除机器人的时间；`added` 中还有添加的场景值 `scene` 与分享链接中的回调数据 `sceneParam`
    - `proactive`：最近一次用户开启或关闭机器人主动消息的结果 `allowed` 与时间
    - `lastMessage`：最近一条单聊消息的时间与用户的昵称（QQ 可能不提供昵称）
  - `status` 取机器人被添加、被移出与最近一条消息中最晚的一项，所以机器人在插件离线期间被重新拉进群时，该群有新消息后就会恢复为 `added`。
  - 收到事件 5 秒后写入这段时间内的全部变化，插件停止时立即写入。每次写入前都会重新读取该文件并合并，所以手动添加的字段（如备注）会保留，手动删除的群或用户要等再次出现在事件中才会重新记录。
  - 该文件不是有效的 JSON 对象时，插件不会覆盖它，只在内核日志中警告；修复或删除该文件后，下一个相关事件会把期间的变化一起写入。插件在此之前停止时，这些变化会丢失。
- 收集箱

  - 群里的每条消息转换为一个超级块，先插入收集箱文档下的 `.temp` 文档，需要时下载其中的资源文件，再移动到收集箱文档下 `YYYY/MM/YYYY-MM-DD` 文档的末尾。日期为消息的发送日期（按思源内核所在设备的时区），缺少的文档会自动创建。
  - 收集箱文档可以移动或重命名。
  - @ 机器人的消息视为指令，不会写入收集箱；@ 全体成员的消息除外，即使它同时 @ 了机器人。
  - 同一条消息被重复推送时只写入一次。
  - 消息的转换方式

    - 文本：一条消息为一个段落，按原样显示（Markdown 语法不会生效），保留换行；@ 成员显示为 <kbd>@昵称</kbd>，QQ 表情显示为 `[表情名称]`，网址转换为链接。
    - 图片：显示在该消息文本的前面（QQ 不提供图片在文本中的位置）。
    - 语音：转换为音频块，后面附上 QQ 的语音识别文本。
    - 视频：转换为视频块。
    - 文件：转换为以文件名命名的链接。
    - 引用消息：正文前是一个引述块。被引用的消息已在收集箱中时，其中是指向它的块引用，锚文本为动态锚文本；否则其中是被引用的内容。
    - 聊天记录（合并转发）：其中的每条消息转换为一个超级块，嵌套的聊天记录也会展开。
    - 卡片等其他消息：以文本显示。
  - 消息块带有以下自定义属性，可以用于查询

    - `custom-author-username`：发送者的昵称，显示在消息块的左上角
    - `custom-author-id`：发送者的 OpenID
    - `custom-msg-idx`：消息在 QQ 中的索引
    - `custom-event-id`：推送该消息的事件的 ID
  - 思源在下载资源文件时退出，会有消息留在 `.temp` 中。插件重新启动后，该收集箱收到第一条消息时，会把这些消息移到对应的日期文档（日期取它们插入 `.temp` 的时间）。
- 上线与下线通知

  - 在绑定中开启「上下线通知」后，机器人上线时会向该群发送「收集箱已上线」通知，下线时发送「收集箱已下线」通知。通知中带有设备名称。该开关默认关闭。
  - 上线：打开 `QQ 机器人 > 机器人 > 上线`，或者在该开关打开时插件开始运行。下线：关闭该开关，或者插件停止运行（被禁用、卸载、更新后重新加载，或者正常退出思源）。通过「只在此设备上运行」换到另一台设备时，原来的设备发送下线通知，新的设备发送上线通知。
  - 只由运行机器人的设备发送。退出思源时最多等待下线通知 5 秒；强制退出、崩溃或被系统终止时不会发送下线通知。
  - 通知是 QQ 的主动消息，受 QQ 的频率限制（每个群每分钟 20 条、每天 1000 条），机器人没有发送主动消息的权限时会发送失败，失败的原因可以在内核日志中查看。
- 指令

  - `/openid`：查询 OpenID

    - 单聊中向机器人发送 `/openid`，机器人会回复你的 user_openid。
    - 群里 @ 机器人发送 `/openid`，机器人会回复你在该群的 member_openid 与该群的 group_openid。
  - 群里只响应群主发送的指令，其他成员发送的指令会被忽略。
  - 群里 @ 机器人的消息都视为指令，不是已知指令的内容（例如「@机器人 你好」）会被忽略，也不会写入收集箱；没有 @ 机器人的消息都不会视为指令。
- 指令面板

  - 机器人上线时，插件会在 QQ 开放平台创建或更新单聊与群聊的指令面板（在 QQ 的输入框中输入 `/` 时显示），默认列出 `openid` 指令，其中群聊的指令仅管理员可以使用。插件运行期间，只有 AppID、AppSecret 或指令面板的配置变化后才会再次同步。
  - 指令面板的配置不在设置面板中。高级用户可以编辑 `data/storage/petal/im-bot/config.json` 中的 `qq.panels`，格式见 QQ 文档[创建指令面板](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_panels.post.html)，其中 `panel.remark` 不能为空，插件用它找到对应的面板。
- 发送消息

  - 在命令面板中运行「打开 QQ 机器人发送消息」（仅桌面端），会打开一个页签，用来以机器人的身份向已知的群与单聊用户发送主动消息。
  - 发送对象从 `chats.json` 中选择（见「已知的群与单聊用户」）。机器人仍在群中（或仍被用户添加）的排在前面，其中最近有活动的排在前面；已将机器人移出的群与已删除机器人的用户会注明。点击「刷新」重新读取，其中包括还没写入 `chats.json` 的变化。
  - 选择发送对象后，页签中显示它的状态、主动消息的开关、群主或 union_openid，以及最近消息与首次记录的时间。
  - 群可以点击「查询群信息」查询群名称、群简介、群分类、群标签与群成员数，查询到的群名称也会显示在发送对象中，并记录到 `chats.json` 中，之后打开页签时也会显示。该接口仅对白名单机器人开放，否则会提示需要向 QQ 开放平台申请权限。
  - 消息类型可以选择文本或 Markdown。向单聊用户发送时可以开启「互动召回」，以互动召回消息（`is_wakeup`）发送。
  - 点击「发送」或按 Ctrl+Enter（macOS 上为 ⌘+Enter）发送，下方显示响应的状态码、耗时、响应头与响应体。状态码为 2xx 且响应体中没有错误码（`err_code`）时才算发送成功，此时清空消息内容；发送失败，或者等待响应时修改了消息内容，则保留。失败的原因见响应体中的错误码。
  - 主动消息受 QQ 的限制：向群发送需要群主为机器人开启「机器人主动在群聊内发言」，向用户发送需要用户在机器人资料卡中开启主动消息；每个群或用户每分钟最多收到 20 条、每天最多 1000 条。互动召回消息只能在用户与机器人对话后的 30 天内发送，当天、1–3 天、3–7 天、7–30 天各 1 条。
  - 消息会真实地发送给群或用户。该功能在所有设备上都可以使用，不受「上线」与「只在此设备上运行」的限制。
- QQ 机器人接口调试

  - 在命令面板中运行「打开 QQ 机器人接口调试」（仅桌面端），会打开一个页签，用来以机器人的身份调用 [QQ 机器人服务端接口](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/api-call-guide.html)。
  - 选择请求方法，填写以 `/` 开头的请求路径（相对于 `https://api.bot.qq.com`，例如 `/gateway/bot`）与 JSON 格式的请求体，点击「发送」或在请求路径中按回车，即可查看响应的状态码、耗时、响应头与响应体。
  - 请求会以机器人的身份发出，调用发送消息等接口会产生实际效果。该功能在所有设备上都可以使用，不受「上线」与「只在此设备上运行」的限制。
- 微信机器人（ClawBot）

  - 在 `微信机器人 > 机器人 > 微信账号` 中扫码登录并打开 `微信机器人 > 机器人 > 上线` 后，插件在思源内核中以长轮询接收发给 ClawBot 的消息，不需要公网地址。登录信息保存在 `data/storage/petal/im-bot/weixin/<机器人 ID>/auth.json` 中。
  - 关闭「上线」后停止接收，再次打开后从上次的接收位置继续。下线期间发给 ClawBot 的消息能否在上线后收到，取决于微信服务端是否保留它们，尚未验证。
  - 在哪台设备上扫码登录，就由哪台设备接收消息。在另一台设备上重新扫码登录后，改由那台设备接收，原来的设备在数据同步后停止。
  - 接收的位置保存在 `data/storage/petal/im-bot/weixin/<机器人 ID>/cursor.json` 中，插件重新启动后从上次的位置继续；重新扫码登录后从头开始。
  - 同一时间只有一个登录：扫码登录了另一个机器人时，上一个机器人的登录信息与接收的位置会被删除，它的事件日志保留。
  - 微信返回登录失效时停止接收，需要重新扫码登录。点击「退出登录」会停止接收，并删除登录信息与接收的位置，事件日志保留。
  - 收到的消息写入 `微信机器人 > 收集箱 > 收集箱文档 ID` 指定的文档，组织方式与 QQ 的收集箱相同：先插入 `.temp`，再移动到 `YYYY/MM/YYYY-MM-DD` 文档的末尾。同一篇文档也可以同时作为 QQ 群的收集箱。
  - 消息的转换方式

    - 每条消息转换为一个超级块，其中每个消息项为一个段落：文本按原样显示，网址转换为链接；图片、语音、文件与视频先显示为 `[图片]`、`[语音]` 加语音转文字、`[文件] 文件名` 与 `[视频]`。
    - 开启 `微信机器人 > 收集箱 > 下载资源文件` 且思源内核能解密时，插件在回复之后从微信 CDN 下载媒体，用 AES-128-ECB 解密并保存为资源文件，再替换占位文本：图片显示为图片，视频显示为视频块，语音与文件显示为指向资源文件的链接（语音保留语音转文字）。消息块的 ID 不变，已发出的块链接与指向它的块引用仍然有效。
    - 下载或解密失败的媒体保留占位文本，内核日志中会有警告。消息带有文件或视频的 MD5 时会校验，不一致时只记录警告，文件仍然保存。
    - 引用消息：正文前是一个引述块。被引用的消息已在收集箱中时，其中是指向它的块引用，锚文本为动态锚文本；否则其中是被引用的内容。
    - 机器人自己发出的消息不会写入，同一条消息被重复收到时只写入一次。
  - 消息块带有自定义属性 `custom-author-id`（发送者的微信用户 ID）与 `custom-msg-id`（消息 ID）。
- Telegram 机器人

  - 填写 Token 并打开 `Telegram 机器人 > 机器人 > 上线` 后，插件在思源内核中以长轮询（getUpdates）接收机器人的消息，不需要公网地址。机器人不能同时设置 Webhook。
  - 本设备的状态显示在 `Telegram 机器人 > 机器人 > 连接状态` 中。请求失败后 2 秒重试，连续失败 3 次后等待 30 秒；超过频率限制时按 Telegram 要求的时间等待。
  - 接收的位置只保存在内存中，由 Telegram 服务端记录哪些消息已经收到。关闭「上线」或插件停止期间发给机器人的消息，Telegram 最多保留 24 小时，再次上线后会补收。
  - 收到的更新都会记录到内核日志中，开启 `Telegram 机器人 > 机器人 > 事件日志` 时还会保存为文件。
- Telegram 收集箱

  - 每条绑定把一个会话（私聊、群组或频道）的消息写入一篇收集箱文档，组织方式与 QQ 的收集箱相同：先插入 `.temp`，再移动到 `YYYY/MM/YYYY-MM-DD` 文档的末尾。同一篇文档也可以同时作为 QQ 群与微信的收集箱。
  - 发给本机器人的指令（如 `/chatid`、`/start@机器人用户名`）与成员变化、置顶等服务消息不会写入；带有其他机器人用户名的指令（如 `/start@other_bot`）按普通消息写入。
  - 同一条消息被重复收到时只写入一次。消息在 Telegram 中被编辑或删除后，收集箱中的内容不会改变。
  - 消息的转换方式

    - 每条消息转换为一个超级块。文本中的格式转换为思源的样式：粗体、斜体、下划线、删除线与行内代码不变，剧透显示为高亮，引用显示为引述块，代码块显示为代码块；文字链接、网址、邮箱与电话号码转换为链接；提及与指令显示为 <kbd>@用户名</kbd>、<kbd>/指令</kbd>，没有用户名的用户显示为 <kbd>@&lt;名称&gt;</kbd>；日期时间转换为行级备注，备注内容为 UTC 时间。其余文本按原样显示，其中的网址转换为链接。
    - 思源不能完整保留的格式：带下划线的文字中有 `*`、`_`、`#`、`[` 等可能组成 Markdown 标记的字符时，不显示下划线；删除线、高亮等样式中有标点时，标点旁边的空格可能不带样式。
    - 媒体先显示为占位文本，如 `[图片]`、`[语音]`、`[文件] 文件名`。开启 `Telegram 机器人 > 收集箱 > 下载资源文件` 时，插件从 Telegram 下载媒体并保存为资源文件，再替换占位文本：图片与静态贴纸显示为图片，视频、视频消息、视频贴纸与动图显示为视频块，语音与音频显示为音频块，文件显示为以文件名命名的链接。思源无法播放动画贴纸（.tgs），它显示为缩略图，后面附上指向贴纸文件的链接。图片只保存最大的尺寸，媒体的说明文字放在媒体后面。
    - Telegram 官方服务器只允许下载 20 MB 以内的文件，更大的媒体以及下载失败的媒体保留占位文本，内核日志中会有警告。
    - 位置显示为指向 OpenStreetMap 的链接；联系人、投票与骰子以文本显示。
    - 回复的消息：正文前是一个引述块。被回复的消息已在收集箱中时，其中是指向它的块引用，锚文本为动态锚文本；否则其中是被回复的内容。回复时引用了部分文字的，锚文本或引述块中是被引用的部分。
  - 消息块带有以下自定义属性

    - `custom-msg-id`：`会话 ID:消息 ID`。消息 ID 只在同一个会话中唯一，所以带上会话 ID
    - `custom-author-id`：发送者的用户 ID；以群组或频道的身份发言时为该群组或频道的 ID
    - `custom-author-username`：发送者的名称（频道中为署名或频道名称），只在群组与频道中记录，显示在消息块的左上角
    - `custom-update-id`：推送该消息的更新的 ID（update_id）
  - 在绑定中开启「回复块链接」后，机器人会回复每条写入该文档的消息，内容为该消息超级块的块超链接 `siyuan://blocks/<块 ID>`；开启「上下线通知」后，机器人上线与下线时向该会话发送通知，发送时机与 QQ 的「上线与下线通知」相同。
- Telegram 指令

  - `/chatid`（以及 `/start`）：机器人回复该会话的 ID，群组中还回复发送者的用户 ID。群组中请发送 `/chatid@机器人用户名`：机器人开启隐私模式时，可能收不到不带用户名的指令。
  - 群组中只响应群主与管理员（包括匿名管理员）发送的指令，其他成员发送的指令只记录日志。
- 飞书机器人

  - 填写 App ID 与 App Secret 并打开 `飞书机器人 > 机器人 > 上线` 后，插件在思源内核中通过飞书的长连接（WebSocket）接收应用订阅的事件，不需要公网地址。长连接只支持企业自建应用。
  - 本设备的连接状态显示在 `飞书机器人 > 机器人 > 连接状态` 中。断线后自动重连，重连间隔从 1 秒逐步增加到 60 秒；超过两个心跳间隔没有收到飞书的任何数据时，视为连接已断开并重新连接。App ID 或 App Secret 无效时停止连接。
  - 收到的事件立即确认（飞书要求 3 秒内确认，否则会重推），被重推的事件只处理一次。
  - 推送失败（包括没有在线的连接）时，飞书约在 15 秒、5 分钟、1 小时与 6 小时后重推，最多 4 次。所以关闭「上线」或插件停止期间发给机器人的消息，会在再次上线后的下一次重推时收到（实测约在消息发送 5 分钟后），离线太久的消息会收不到。
  - 飞书把每个事件只推送给应用的其中一个长连接，有多台设备时请开启「只在此设备上运行」。
  - 收到的事件都会记录到内核日志中，开启 `飞书机器人 > 机器人 > 事件日志` 时还会保存为文件。
- 飞书收集箱

  - 每条绑定把一个会话（单聊或群聊）的消息写入一篇收集箱文档，组织方式与 QQ 的收集箱相同：先插入 `.temp`，再移动到 `YYYY/MM/YYYY-MM-DD` 文档的末尾。同一篇文档也可以同时作为其他平台的收集箱。
  - 同一秒内连发的几条消息，到达的顺序可能与发送顺序不同。所以消息先等待 1 秒（从第一条开始最多 3 秒），按发送时间排序后再写入。
  - 发给本机器人的指令（以 `/` 开头的文本消息，群聊中要 @ 机器人）与系统消息不会写入；@ 了机器人但不是指令的消息照常写入。
  - 同一条消息被重复收到时只写入一次。消息在飞书中被编辑或撤回后，收集箱中的内容不会改变。
  - 消息的转换方式

    - 每条消息转换为一个超级块。文本按原样显示（Markdown 语法不会生效），保留换行，网址转换为链接，@ 显示为 <kbd>@名称</kbd>，表情显示为 `[看]` 这样的文本。
    - 富文本：标题显示为粗体，粗体、斜体、下划线、删除线与超链接转换为思源的样式，代码块与分割线转换为对应的块，表情显示为 `[表情名]`。飞书推送的富文本中，行内代码、列表与引用只是普通文本，按文本显示。
    - 媒体先显示为占位文本，如 `[图片]`、`[语音]`、`[文件] 文件名`。开启 `飞书机器人 > 收集箱 > 下载资源文件` 时，插件从飞书下载媒体并保存为资源文件，再替换占位文本：图片显示为图片，视频显示为视频块，语音显示为音频块，文件显示为以文件名命名的链接。消息块的 ID 不变。
    - 表情包与文件夹不能下载，保留占位文本；超过 100 MB 的媒体与下载失败的媒体也保留占位文本，内核日志中会有警告。
    - 聊天记录（合并转发）：其中的每条消息转换为一个超级块，左上角显示发送者的名称，嵌套的聊天记录也会展开，其中的媒体同样会下载。
    - 回复的消息：正文前是一个引述块。被回复的消息已在收集箱中时，其中是指向它的块引用，锚文本为动态锚文本；否则其中是被回复的内容。
    - 群聊中，获取聊天记录的内容与被回复的消息需要 `im:message.group_msg` 权限；没有该权限时，聊天记录显示为 `[聊天记录]`，不在收集箱中的被回复消息显示为「引用的消息」。
    - 位置显示为指向 OpenStreetMap 的链接；卡片、群名片、联系人、日程、任务、投票与视频通话显示为占位文本与其中的主要信息。
  - 消息块带有以下自定义属性

    - `custom-msg-id`：消息 ID（message_id）
    - `custom-author-id`：发送者的 open_id
    - `custom-author-username`：发送者的名称，只在群聊中记录，显示在消息块的左上角。名称取自群成员列表（每个群每分钟最多获取一次）与消息中的 @，需要 `im:chat:readonly` 权限
    - `custom-event-id`：推送该消息的事件的 ID
  - 在绑定中开启「回复块链接」后，机器人会回复每条写入该文档的消息，内容为该消息超级块的块超链接 `siyuan://blocks/<块 ID>`；开启「上下线通知」后，机器人上线与下线时向该会话发送通知，发送时机与 QQ 的「上线与下线通知」相同。
- 飞书指令

  - `/chatid`：机器人回复该会话的 ID 与发送者的 open_id。群聊中要 @ 机器人发送。
  - 群聊中只响应群主与群管理员发送的指令（插件用 `im:chat:readonly` 权限获取群主与群管理员），其他成员发送的指令只记录日志。
- 数据文件

  - 插件的数据保存在工作空间的 `data/storage/petal/im-bot/` 中，会随数据同步：`config.json` 是插件的设置，各机器人的其他数据保存在以机器人 ID 命名的目录中。
  - QQ：`qq/<AppID>/chats.json`（已知的群与单聊用户）与 `qq/<AppID>/events/`（事件日志）。
  - 微信：`weixin/<机器人 ID>/auth.json`（登录信息）、`weixin/<机器人 ID>/cursor.json`（接收的位置）与 `weixin/<机器人 ID>/events/`（事件日志）。
  - Telegram：`telegram/<机器人 ID>/events/`（事件日志）。
  - 飞书：`feishu/<App ID>/events/`（事件日志）。
  - 微信与 Telegram 当前的机器人 ID 由插件写入 `config.json` 的 `weixin.botId` 与 `telegram.botId`：微信在扫码登录时写入、退出登录时清空，Telegram 在连接成功后写入。

### 设置项介绍

- `常规设置`

  - `重置设置选项`

    - 把所有设置选项恢复为默认值，确认后会刷新界面
- `QQ 机器人`

  - `机器人`

    - `上线`

    - `连接状态`

      - 显示本设备上机器人与 QQ 的连接：已连接（连接时间与机器人的名称）、正在连接、连接已断开（下次连接的时间与断开的原因）、已停止连接（原因），以及已下线、只在其他设备上运行、没有填写 AppID 或 AppSecret、没有订阅事件等不连接的情况

    - `AppID QQ_BOT_APPID`

      - QQ 开放平台中机器人的 AppID，在机器人的开发设置中获取
    - `AppSecret QQ_BOT_SECRET`

      - QQ 开放平台中机器人的 AppSecret，用于获取接口调用凭证
      - 以明文保存在工作空间的 `data/storage/petal/im-bot/config.json` 中，会随数据同步
    - `订阅事件 QQ_BOT_INTENTS`

      - 机器人要接收的事件类别，每个开关对应一个类别，各类别包含的事件见 QQ 文档[事件订阅与通知](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/event-emit.html)
      - 默认开启「群聊与单聊」与「频道 @ 机器人消息」；收集箱与指令只需要「群聊与单聊」
      - 按 QQ 文档，频道、频道成员与频道 @ 机器人消息以外的类别可能需要先在 QQ 开放平台申请权限。订阅了没有权限的类别时，QQ 会关闭连接（错误码 4014），插件随后停止重连
      - 修改后自动重新连接；全部关闭时不连接机器人
    - `事件日志`

      - 开启后，把收到的每个事件保存为工作空间中的一个 JSON 文件 `data/storage/petal/im-bot/qq/<AppID>/events/<事件类型>/<事件 ID>.json`，其中的 group_openid 等信息可用于配置绑定
      - 没有事件 ID 的事件（`READY`、`RESUMED`）不会保存
      - 这些文件会随数据同步，插件不会自动删除它们；不需要排查问题时可以关闭
      - 默认关闭，修改后对之后收到的事件生效
    - `只在此设备上运行`

      - 开启后只有本设备连接机器人：写入事件日志、收集箱与 `chats.json`、响应指令、发送上线与下线通知、同步指令面板。设置同步到其他设备后，那些设备会断开连接
      - 关闭时，上线后每台安装了本插件的设备都会连接机器人
      - 开关下方显示本设备的 ID 与当前指定的运行设备

      - 点击「添加绑定」新增一条绑定，点击「删除」删除该绑定，修改会立即保存

      - `启用`：关闭后该绑定不再写入消息，也不再发送上线与下线通知。群或文档 ID 为空的绑定同样不生效。新建的绑定默认不启用

    - `只在此设备上运行`

      - 开启后只有本设备连接飞书：写入事件日志与收集箱、响应指令、发送上线与下线通知。飞书把每个事件只推送给其中一个连接，有多台设备时请开启
      - 关闭时，上线后每台安装了本插件的设备都会连接飞书，消息会随机分散到各台设备
      - 开关下方显示本设备的 ID 与当前指定的运行设备
  - `收集箱`

    - `绑定会话`

      - 每条绑定把一个会话的消息写入一篇收集箱文档；一个会话可以绑定多篇文档，一篇文档也可以绑定多个会话
      - `会话 ID`：以 `oc_` 开头的 chat_id，单聊与群聊都有。向机器人发送 `/chatid`（群聊中由群主或群管理员 @ 机器人发送）可以查询，也可以在事件日志中找到
      - `收集箱文档 ID`：用来收集消息的文档的 ID。在文档树中右键该文档，选择「复制 > 复制 ID」即可获得
      - `启用`：关闭后该绑定不再写入消息，也不再发送上线与下线通知。会话或文档 ID 为空的绑定同样不生效。新建的绑定默认不启用
      - `回复块链接`：开启后，机器人回复每条写入该文档的消息，内容为该消息超级块的块超链接。默认关闭
      - `上下线通知`：开启后，机器人上线与下线时向该会话发送通知。一个会话的多条绑定都开启了通知时，每次只发送一条。默认关闭
    - `下载资源文件`

      - 开启后，把消息（包括聊天记录）中的图片、语音、视频与文件下载为工作空间中的资源文件，见「飞书收集箱」。飞书只提供 100 MB 以内的文件
      - 默认开启，修改后对之后收到的消息生效
